# ميزان — تطبيق الإدارة المالية الشخصية والعائلية

تطبيق ويب عربي (RTL) يعمل على الموبايل والكمبيوتر ويُثبَّت على الشاشة الرئيسية (PWA): دخل، مصروفات، أقساط وديون، جمعيات، ميزانية، ادخار، حسابات، تقويم مالي، تقارير سنوية، وعملات متعددة — مع مزامنة سحابية بين أجهزتك.

> **حالة هذه النسخة:** المحرك المالي والواجهة مختبَران آلياً (13 اختبار حسابات + اختبار واجهة كامل في متصفح حقيقي بالوضع المحلي). **الربط الحي مع Supabase لم يُختبر** لأن إنشاء المشروع والنشر يتمان من حسابك أنت؛ نفّذ «قائمة التحقق بعد النشر» في آخر هذا الملف.

---

## 1. التقنيات ولماذا

| الجزء | الاختيار | السبب |
|---|---|---|
| الواجهة | HTML/CSS/JavaScript (ES Modules) بلا خطوة بناء | يُنشر كملفات ثابتة على أي استضافة مجانية، ولا يحتاج Node أو تثبيت حزم |
| قاعدة البيانات | **Supabase** (Postgres) | قاعدة علاقية حقيقية، دخول بالبريد وكلمة المرور، Row Level Security، ومزامنة فورية — ضمن الخطة المجانية |
| العمل بلا إنترنت | IndexedDB + صندوق صادر | تُحفظ العمليات محلياً وتُرفع عند عودة الاتصال |
| التثبيت | Web App Manifest + Service Worker | إضافة للشاشة الرئيسية على Android و iPhone |
| الرسوم | SVG مكتوبة داخل المشروع | لا مكتبات خارجية، تعمل بلا إنترنت |
| أسعار الصرف | open.er-api.com (مجاني بلا مفتاح، تحديث يومي) + إدخال يدوي | لا اشتراك مدفوع |

**لماذا Supabase وليس Firebase؟** البيانات المالية علاقية (عمليات ↔ حسابات ↔ ديون ↔ جمعيات) وتناسبها SQL، وصلاحيات RLS تُكتب مرة واحدة في القاعدة، ويمكن تصدير القاعدة كاملة لاحقاً.

**التكلفة:** صفر. حدود الخطة المجانية في Supabase (500MB قاعدة بيانات، مشروعان) تكفي استخدام أسرة لسنوات طويلة. **تنبيه مهم:** المشروع المجاني يتوقف مؤقتاً إذا مرّ أسبوع بلا أي نشاط؛ الاستخدام اليومي يمنع ذلك، وإن توقف تعيد تشغيله من لوحة Supabase بضغطة (البيانات لا تُحذف). الخطة المدفوعة (25$ شهرياً) تلغي هذا التوقف وتضيف نسخاً احتياطياً يومياً — غير ضرورية للبداية.

## 2. النشر خطوة بخطوة (حوالي 15 دقيقة)

### أ) قاعدة البيانات
1. أنشئ حساباً مجانياً في [supabase.com](https://supabase.com) ثم **New project** (اختر كلمة مرور قوية للقاعدة ومنطقة قريبة منك).
2. من القائمة: **SQL Editor → New query**، الصق محتوى الملف `supabase/schema.sql` كاملاً واضغط **Run**. ينشئ 9 جداول مع RLS والمزامنة الفورية.
3. من **Project Settings → API** انسخ: **Project URL** والمفتاح العام (**anon / publishable**).
4. افتح `js/config.js` وضع القيمتين:
   ```js
   export const SUPABASE_URL = 'https://xxxx.supabase.co';
   export const SUPABASE_ANON_KEY = 'eyJ...';
   ```
   المفتاح العام آمن للنشر لأن كل جدول محمي بـ RLS. **لا تضع مفتاح `service_role` أبداً.**

### ب) الاستضافة (اختر واحدة — كلها مجانية)
- **Netlify (الأسهل):** ادخل [app.netlify.com/drop](https://app.netlify.com/drop) واسحب مجلد المشروع كاملاً. ستحصل على رابط ثابت مثل `https://اسم.netlify.app`.
- **Cloudflare Pages / Vercel / GitHub Pages:** ارفع المجلد كموقع ثابت، بلا أمر بناء (Build command فارغ، ومجلد الإخراج هو الجذر).

### ج) ربط الرابط بالدخول
في Supabase: **Authentication → URL Configuration** ضع رابط موقعك في **Site URL** وأضفه إلى **Redirect URLs** (لازم لروابط تأكيد البريد واستعادة كلمة المرور).

### د) أول دخول
1. افتح الرابط → **إنشاء حساب جديد** بالبريد وكلمة المرور → افتح رابط التأكيد في بريدك → سجّل الدخول.
2. اختر العملة الأساسية، ثم أدخل أرصدة حساباتك الحالية من صفحة «الحسابات».
3. (اختياري لمنع أي تسجيل آخر) بعد إنشاء حسابك: **Authentication → Sign In / Providers → عطّل Allow new users to sign up**.

> بريد التأكيد يُرسل من خادم Supabase الافتراضي وهو محدود بعدد قليل من الرسائل في الساعة — كافٍ لحساب أو اثنين.

### هـ) التثبيت على الموبايل
- **Android (Chrome):** القائمة ⋮ → «إضافة إلى الشاشة الرئيسية / تثبيت التطبيق».
- **iPhone (Safari):** زر المشاركة → «إضافة إلى الشاشة الرئيسية».

## 3. الاستخدام اليومي

| ماذا تريد | أين |
|---|---|
| إضافة مصروف بسرعة | الزر الأخضر **＋** أسفل الشاشة: المبلغ ← التصنيف ← حفظ |
| تسجيل راتب/دخل، أو دخل متوقع | «الدخل» ← تسجيل دخل. الراتب المتكرر: «دخل شهري متكرر» ثم «تسجيل الاستلام» كل شهر |
| تعديل أو حذف أي عملية | اضغط عليها في أي قائمة |
| إيجار/فواتير/اشتراكات شهرية | «التقويم» أو «الإعدادات» ← مصروف متكرر؛ تظهر كتنبيه حتى تضغط «تسجيل الدفع» |
| دين أو قسط | «الأقساط والديون» ← جديد. ثم «تسجيل دفعة» بأي مبلغ (جزئي أو مبكر) |
| جمعية | «الجمعيات» ← جديدة. «دفع اشتراك» شهرياً و«تسجيل الاستلام» عند دورك |
| ميزانية لكل تصنيف | «الميزانية» ← اضغط التصنيف |
| هدف ادخاري | «الادخار» ← هدف جديد ← إيداع/سحب |
| تحويل بين حساباتك | «الحسابات» ← تحويل (ليس دخلاً ولا مصروفاً) |
| مطابقة رصيد حساب مع البنك | «الحسابات» ← الحساب ← تسوية الرصيد |
| تقرير سنة أو فترة، طباعة/PDF، Excel | «التقارير» |
| العملات وأسعار الصرف، التصنيفات، النسخ الاحتياطي | «الإعدادات» |

**PDF:** زر «طباعة / حفظ PDF» يفتح نافذة الطباعة؛ اختر «حفظ كـ PDF». **Excel:** ملفات CSV تُفتح مباشرة في Excel بالعربية.

**نسخة احتياطية:** «الإعدادات ← تنزيل نسخة احتياطية (JSON)». يُنصح بها شهرياً حتى مع المزامنة السحابية.

## 4. الأمان وحفظ البيانات

- الدخول عبر Supabase Auth: كلمات المرور تُخزَّن مشفّرة (hash) ولا تمر على كود التطبيق كنص محفوظ.
- كل جدول عليه Row Level Security: لا يقرأ ولا يكتب المستخدم إلا صفوفاً `user_id` فيها = معرّفه، والخادم يمنع نقل صف لمستخدم آخر.
- المصدر الأساسي للبيانات هو قاعدة Postgres. النسخة داخل المتصفح (IndexedDB) للعمل بلا إنترنت فقط، وتُمسح من الجهاز عند تسجيل الخروج.
- الاتصال كله عبر HTTPS.

**الوضع المحلي:** إذا تُرك `js/config.js` فارغاً يعمل التطبيق على الجهاز فقط (بلا دخول ولا مزامنة). حدوده: البيانات في هذا المتصفح وحده وقد تُفقد بمسح بيانات المتصفح. للانتقال إلى جهاز آخر أو إلى النسخة السحابية: تنزيل نسخة احتياطية ثم «استعادة».

---

## 5. ما لا تفعله هذه النسخة (بصراحة)

- **إشعارات والتطبيق مغلق:** تحتاج خادم Web Push وجدولة — غير مضمَّنة. الموجود: تنبيهات داخل التطبيق دائماً، وإشعار نظام عند فتح التطبيق (مرة يومياً) إن فعّلته.
- **التعارض:** «آخر تعديل يفوز» لكل عملية اعتماداً على ساعة الجهاز؛ جهاز ساعته خاطئة كثيراً قد يفوز تعديله خطأً.
- **حساب واحد = ملف مالي واحد.** لمشاركة الأسرة استخدموا نفس الحساب على عدة أجهزة. تعدد المستخدمين داخل أسرة واحدة بصلاحيات مختلفة تطوير لاحق.
- **الديون التي لي عند الآخرين** و**الفوائد المتغيرة** غير مدعومة؛ أدخل إجمالي الدين شاملاً الأرباح.
- **أسعار الصرف المبدئية تقريبية** إلى أن تُحدَّث (آلياً عند أول اتصال، أو يدوياً من الإعدادات).

## 6. بنية المشروع

```
index.html            الهيكل
css/app.css           التصميم (Mobile First, RTL, طباعة)
js/config.js          ← مفاتيح Supabase (الملف الوحيد الذي تعدّله)
js/schema.js          تعريف الجداول والثوابت (مصدر واحد للتطبيق ولـ SQL)
js/calc.js            المحرك المالي (كل المعادلات)
js/store.js           التخزين المحلي + المزامنة + النسخ الاحتياطي
js/ui.js              نماذج، نوافذ، رسوم بيانية
js/tx.js              نموذج العمليات الموحد والقوائم
js/views1..3.js       الصفحات
js/app.js             الإقلاع والدخول والتنقل
sw.js, manifest.webmanifest, icons/   PWA
supabase/schema.sql   قاعدة البيانات (مولَّد: node tools/gen-sql.mjs)
docs/FORMULAS.md      توثيق المعادلات
tests/                اختبارات الحسابات والواجهة
```

**للتطوير:** أضف العمود في `js/schema.js` ثم `node tools/gen-sql.mjs` وأضف `alter table` يدوياً للقاعدة القائمة. الاختبارات: `node --test tests/*.test.mjs`، والتشغيل المحلي: `python3 -m http.server 8080`. عند تعديل الملفات غيّر `CACHE` في `sw.js` (مثلاً `mizan-v2`).

## 7. قائمة التحقق بعد النشر

1. إنشاء حساب ← وصول بريد التأكيد ← الدخول ← اختيار العملة.
2. أضف مصروفاً من الموبايل ← يظهر على الكمبيوتر خلال ثوانٍ دون تحديث (مؤشر «متزامن» أعلى الشاشة).
3. فعّل وضع الطيران، أضف مصروفاً (المؤشر: «1 بانتظار الرفع»)، أعد الاتصال ← يصبح «متزامن» ويظهر على الجهاز الآخر.
4. عدّل نفس العملية من جهازين ← تستقر على آخر تعديل في الجهازين.
5. أنشئ حساباً ثانياً ببريد آخر ← يجب ألا يرى أي بيانات من الأول.
6. نسيت كلمة المرور ← يصل الرابط ويفتح نموذج كلمة المرور الجديدة.
7. الإعدادات ← «تحديث من الإنترنت» لأسعار الصرف.
8. تثبيت على الشاشة الرئيسية ← يفتح بلا إنترنت.

إن ظهر «تعذرت المزامنة» فنص الخطأ يظهر في «الإعدادات ← الحساب والمزامنة»؛ الأسباب المعتادة: لم يُشغَّل `schema.sql`، أو خطأ في القيمتين داخل `config.js`.
